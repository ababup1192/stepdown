# ひとあし迷宮（仮）— 計画 改訂 2

縦 540×960 のスマホブラウザ向けターン制ローグライク。入力は方向だけ。行動は立ち位置の法則で決まる。5 階で終わる。
見た目は Blender の 3D ダンジョン＋人形風の 2D キャラをビルボードで置く＋斜め固定のカメラで追従。engine は無改修。

読む先例: `~/Documents/flix_ge_workspace/dungeon3d_lab`（3D ダンジョン・`Res.floorAt`・FloorsDoc）、
`lamplighter`（Kit・Cam.smoothDamp・水の材質・PostView）、`fps3d_lab`（`web/WebMain.flix` の `withProject3d`）。

---

## 1. 状態の分け方
- `Run`（決まりの状態・純粋）: 階の番号・盤（型の番号）・主人公（位置・HP・最大 HP・剣と盾の段）・持ち物（矢・爆弾・薬の段と数）・敵の列・床のアイテム・見たマスの Set・乱数の状態（Int64 の splitmix。Random の effect は使わない）・補正（`Perks`、カードの効果。最初は空）・歩いた数
- `World`（見せる状態）: `{ run, screen, shown, queued, cam, clock, realT, events }`
  - `screen`: `Title | Play | Cards(3 枚) | Dead | Clear`
  - `shown`: 今見せている 1 手分 `{ before: Run, events: List[Event], timeline, startedAt }`。ダッシュ中は残りの手の列も持つ
  - `queued`: 溜めた入力（1 つまで）
- fingerprint と flow の比べは `Run` だけを見る
- tidepool の Worldline（取り消し）・Solve・Tide・水位・EcsTween は消す

## 2. 盤とマス
マスの種類は enum 1 つにまとめ、どの判定もその性質の表を引く。

| マス | 歩ける | 飛べる（コウモリ） | 矢を止める | 見通しを止める |
|---|---|---|---|---|
| 床 | ○ | ○ | × | × |
| 壁 | × | × | ○ | ○ |
| 柱 | × | × | ○ | ○ |
| 岩 | × | × | ○ | × |
| 水 | × | ○ | × | × |
| 階段 | ○ | ○ | × | × |

- 隣 = 上下左右の 4 近傍（斜めには動かない・斜めは殴らない）。爆弾の範囲だけ 8 近傍
- 盤は Doc の文字の地図から作る。マスごとに部屋の番号（通路は 0）を持つ
- 物が占めるマスは `Set[(Int32, Int32)]` で持つ（ボスの 2×2 に備える）

## 3. 1 手（`step(run, input) -> (Run, List[Event])`・純粋）
入力: `Move(d)`（4 方向）か `Wait`。

1. `Move(d)` の行き先 t
   - t に敵 → **殴る**（剣の段の攻撃。移動しない。この手は 3 の判定をしない）
   - t が歩けない → 何も起きない（手を進めない。予告で「×」を出す）
   - それ以外 → t へ移動し、アイテムがあれば拾う（**拾う → 判定** の順）
   - `Wait` → その場に「移動した」とみなす。主人公が階段の上なら**降りる**（次の階へ。この手はここで終わる）
2. 移動か待つの後、その位置で 1 つだけ判定する
   1. 8 近傍に**起きている**敵が `bombNeeds`（Doc・2）体以上 かつ 爆弾 ≥ 1 → **爆弾**（範囲内の敵。壁は越える。自分は無傷）
   2. 上下左右の直線で、距離 `arrowMin..arrowMax`（Doc・2〜4）に敵がいて、間に「矢を止める」マスと敵が無い かつ 矢 ≥ 1 → **矢**。候補が複数なら 近い順 → 上・右・下・左 の順で 1 体。距離 1 には撃たない
3. 敵の手番。主人公に近い順（同じ距離なら作られた順）に 1 体ずつ。倒れた敵・眠っている敵は動かない
   - 主人公が隣（4 近傍）にいる → 殴る
   - 弓兵: 主人公と列がそろい、距離 2〜4 で間が空いていれば撃つ（矢は敵でも止まる）。そうでなければ列をそろえる方へ 1 マス
   - ゼリー・群れ: 歩ける道の BFS で主人公へ 1 マス（ほかの敵のマスには入らない。先に動いた敵が空けたマスには入れる）
   - コウモリ: 2 手に 1 回、乱数の方向へ 1 マス（飛べるマス）
4. 盾: 受ける攻撃を段の分だけ減らす。銀の盾の「弾く」は乱数で、予告には出さない（当たる予告のまま）
5. **倒れる判定の前に薬**: HP ≤ `floor(最大 HP × potionAt)`（Doc・0.25。0 以下も含む）かつ 薬 ≥ 1 → 薬を使う
6. HP ≤ 0 → 倒れる（`Dead` の画面）
7. 歩いた数 `regenEvery`（Doc・12）ごとに HP +1

### 予告（作りで一致を保証）
- 方向の予告: `preview(run, input) = summarize(step(run, input))`。5 つの入力（4 方向＋待つ）でそれぞれ本物の step を回し、出来事の列を「殴る・矢・爆弾・薬・移動・×・降りる・受けるダメージ」に要約するだけ。予告専用の判定は書かない
- 敵の予告（床の赤）: 「主人公の手の後にここにいたら当たるマス」= 起きている各敵の 4 近傍と、弓兵の射線（距離 2〜4、止まるまで）。敵を倒した場合だけ外れる（予告は当たる側に倒れる）
- テスト: ランダムな Run を数百通り作り、`preview` が `summarize(step)` と等しい／敵の予告のマスに居たら被弾する

### ダッシュ
- `dash(run, d) -> List[(Run, List[Event])]` を始めた時に最後まで計算する（1 歩ずつ同じ `step` を通す）
- 止まる条件（その歩で止まる）: 敵が見えた（同じ部屋にいる、または BFS の歩く距離 ≤ `sightSteps`（Doc・5））・アイテムを拾った・階段に乗った・次が歩けない・分かれ道・部屋の入口（部屋の番号が変わる）・HP が減った
- 一本道の通路の角は自動で曲がる
- 始めた時に敵が見えている → 1 歩だけ
- 見せる側は、列を 1 歩ずつ流す。ダッシュ中のタップは「次の歩で止める」だけ（溜めない）。通常の見せ中の入力は 1 つだけ溜め、来たら今の時刻表を最後まで飛ばしてから次を始める

## 4. アイテム（上位互換）
- 系統: 剣・盾（数なし）、矢・爆弾・薬（数あり・上限は Doc: 矢 15・爆弾 5・薬 3）
- 上の段を拾う → 手持ち全部がその段になり、数も足す（上限で切る）
- 同じ・下の段（数あり）→ 今の段の数として足す
- 下の段の剣・盾 → 拾って消える。記録に「木の剣は 今のより弱い」
- 効果の種類（貫通・押し出し・眠り・燃える）はコードの enum。数値（攻撃・範囲・回復量・貫通数）は Doc

| 系統 | 段 |
|---|---|
| 剣 | 木 → 鉄 → 銀（押し出し） |
| 盾 | 木 → 鉄 → 銀（たまに弾く） |
| 矢 | 木 → 鉄（1 体貫通）→ 銀（2 体貫通）→ 火（燃える） |
| 爆弾 | 小（8 近傍）→ 大（2 マス）→ 眠り玉（3 手眠らせる） |
| 薬 | 薬草 → 回復薬 → 万能薬 |

## 5. 階
- 階の形（壁・床・柱・水・岩・階段・松明の位置・苔）は Doc の文字の地図。各階 2 通り（試作は 1F の 2 通りだけ）
- 乱数は 敵・アイテムの置き場と、どちらの地図を使うかだけ。種は `hash(周回の種, 階)`
- 決まり: 主人公の始まりは地図の印。敵は始まりから BFS で 5 歩以上。アイテムは床だけ（階段の上は置かない）
- テスト: 各地図で階段まで歩いて着ける・始まりの近くに敵がいない・アイテムが床にある・同じ種から同じ階
- 5 階: ボス（試作の後）。倒すと `Clear`
- 階の間: `Cards` の画面で 3 枚から 1 枚をタップで選ぶ（試作の後。`Perks` の欄だけ先に持つ）
- 小さい地図は見たマスだけ出す（霧）

## 6. Doc（外形 7 点を満たす。名前は `stepdown.<種類>.json`）
- `stepdown.rules.json`: 秒（1 歩・ダッシュの 1 歩・殴る・矢）・見える距離・矢の射程・爆弾が出る数・薬の閾値・最大 HP・素の攻撃・持ち物の上限・自然回復・タップで待つとみなす半径
- `stepdown.items.json`: 段ごとの数値
- `stepdown.enemies.json`: 敵ごとの HP・攻撃・初出の階・数（動き方は enum の名前）
- `stepdown.floors.json`: 地図（文字）と階ごとの敵・アイテムの数
- `stepdown.look.json`: カメラ（角度・距離・追従の速さ）・光（環境光・松明・手もとの灯り・太陽の影）・水の色・後処理
- `stepdown.text.json`: 記録の文言（「{敵}が となりに にじりよってきた！」など）
- 出さない: 判定の式・敵の動き方・効果の種類（enum）

## 7. 描き方
### 描く元（Res・`Res.build` で 1 回だけ作る）
- `kit.glb`（済み）をノード名で引く（Kit.place の形）
- **地図ごとに、動かない物（床・壁・壁の上面・柱・岩・水場の底・苔・階段・松明の棒）を材質ごとに 1 つの形へつなぐ**。`Res.floorAt(res, 地図の番号)` で引く（dungeon3d_lab と同じ考え。lamplighter の `Town.joined` は群の中で二乗になっているので、写す時は先頭に足して最後に反転する）
- 水面は地図ごとに 1 枚の形（半透明・ShaderDoc の流れる模様・少しの金属っぽさ）
- キャラ・アイテム・アイコンの絵は project.json の textures に登録する（未登録は起動で落ちる）
### 光
- 環境光は暗い青。松明は点光源（地図の印の位置。上限 8 なので、主人公から遠い物から削る）。主人公の手もとの灯り 1 本
- 影は 0.92 の太陽の光（正射影の影の地図）で、柱・壁・キャラの丸い影でない形の影を出す。スポットとどちらが良いかは段 4 で見て決める
- 後処理: トーンマップ・弱いブルーム・FXAA・周辺を暗く
### キャラ
- `Scene3d.billboard`（α 0.5 で切る・カメラに正対）。足もとに丸い影（半透明の円）
- 動きは View が `(前の Run, 出来事の列, 時刻表の進み)` から純粋に導く: 待機の揺れ（実時間）・移動の弧・殴るときの踏み込み・当たって白く光る（tint）・倒れて縮む・矢の板が飛ぶ・爆弾の光と煙
### 床の印
- 4 方向の予告の枠、敵の予告（赤い枠・赤い破線）は、床から少し浮かせた半透明の形。奥行きで決まるので、水との重なりは段 4 で見る
- アイコンと文字（「↑ 矢 -1」）は 2D で、`Camera3d.worldToScreen` でマスの上に置く
### UI（2D）
- 上: 階・HP の棒・剣と盾の段・小さい地図（霧）
- 下: 2 行の記録・持ち物 3 枠（上に条件、ふちの色で段）。上位を拾うと枠が光る
- 字は記録・UI の文言の Doc から subset を作り直す（豆腐を出さない）

## 8. 時計と見せ方
- 遊びの時計 `Clock.Clock[Play]` を World に置き、`App.addClock` で進める。`Cards`・確認の窓では止める
- 待機の揺れ・松明の揺らぎは実時間（`frame#realNow`）
- 1 手の出来事の列から `Timeline.build` で時刻表を組む（タグは `(番号, 出来事の種類)`）。描く側は `Timeline.progressOn`、音は `Timeline.soundsOnClock`
- EcsTween は使わない

## 9. 入力
- タップは「離した時の 1 コマだけの押し」で読む。押しっぱなしのコマが続く時（横の払いの最中）は盤の入力にしない
- 方向は `Camera3d.screenPointToRay` で床の面との交わりを出し、主人公のマスとの差（マス単位）の大きい軸で決める。主人公のマスの中（半径は Doc）は待つ。下の UI の帯は盤の入力にしない
- スワイプは project.json の `web.touchGestures` で swipeUp/Down/Left/Right → dashUp…。デスクトップは Shift＋矢印
- `web.orientation: "portrait"`。ホイールには意味を持たせない
- 短い払い・斜めの払いが落ちるのは仕様として受け入れ、段 6 の実機で確かめる
- e2e の flow は `E2e.table` に「上へ 1 歩」「左へダッシュ」の役を足して、役で書く。タップの座標 → 方向の対応は純粋な関数のテストで押さえる

## 12. 決めた細部（レビュー 2 回目・81 点の残り）
- **敵が起きる**: 階の始めは全員眠り。主人公の手の後・敵の手番の前に判定し、主人公と同じ部屋（部屋の番号が同じ・0 でない）か、歩く距離 ≤ `wakeSteps`（Doc・5）で起きる。以後は起きたまま。眠り玉は「残りの眠る手の数」を同じ欄に持つ。ダッシュの「敵が見えた」はこの判定と同じ関数（起きている敵がいる、または今の手で起きた）
- **step の引数**: `step(ctx, run, input)`。`ctx = { rules, items, enemies, board }`。Doc を読み直した時は今の階を同じ種で作り直す
- **予告のテスト**: 「予告に無いマスに立った Run を数百通り → その手で主人公の被ダメージ 0」。summarize は要約の表のテストを持つ
- **予告の射線**: 地形（矢を止めるマス）だけで止める（敵では止めない。当たる側に倒す）
- **summarize の規則**: 弾いた出来事は「盾で減らした後のダメージ」として数える。コウモリの行き先が方向の予告に出るのは受け入れる（被弾の有無として見えるだけ）
- **タップ**: World に `press: Option[{ at, startedAt }]`。`mouseClicked` で始め、`mouseDown == false` の最初のコマで確定（同じコマでもよい）。押してから動いた距離が `tapSlop`（Doc）を超えたら捨てる。同じコマにダッシュの操作が来たら捨てる。この 3 つは純粋な関数でテストする
- **ダッシュの進め方**: 1 歩見せ始めるごとに、列のその歩の Run を `world.run` にする。止めたら残りの列を捨てるだけ（巻き戻さない）。止まる条件に「その歩で矢か爆弾を使った」を足す
- **予告の作り置き**: `world.preview` に持ち、`run` が変わった時だけ作り直す
- **敵の順**: 主人公への歩く距離（BFS）の近い順 → 作られた順
- **ゼリーの道**: BFS で主人公へ近づく次のマス。同点は 上・右・下・左。次のマスを敵が塞いでいたら、ほかの同点のマス、無ければ待つ
- **コウモリ**: 敵ごとの手の数を数え、偶数の手に動く
- **自然回復**: 移動した手だけ数える（待つ・殴るは数えない）
- **倒れた後**: HP ≤ 0（薬の後）になったら、残りの敵は動かない
- **爆弾の判定の範囲**: どの段も 8 近傍で数える。当たる範囲だけ段で広がる
- **霧**: 部屋に入ったら部屋全体と壁を見たことにする。通路は主人公の 8 近傍
- **試作の 1F から降りたら**: `Clear` の画面。周回の種は flow とテストでは固定、ブラウザとデスクトップでは起動時刻
- **光**: 松明は全部 `pointLights` に入れる（選ぶのは engine の `pickLights`）。地図は画面に入る松明が 7 本以下になるよう描く。キャラは丸い影のまま（ビルボードは影を受けない・落とさない）
- **Doc**: 敵の数は `floors.json` に寄せる（`enemies.json` は敵ごとの強さだけ）。段の並びはコードの enum で、`items.json` は enum の名前をキーに数値だけ（Doc で段は足せない）。秒は `look.json`
- **段 1 の追加**: project.json の design / window（540×960・窓 540×960）・title。tidepool の名前の Doc（theme・scenes・mixer・keys）を stepdown に。keys の undo・restart を消し、dashUp/Down/Left/Right を足す
- **段 4 の追加**: `web/WebMain.flix` を fps3d_lab から写して作る（`withProject3d`）
- **絵**: 盾のアイコンと群れの絵が無い（群れはゼリーを小さく色違いで代用・盾は段 5 で作る）
- **時計**: `Timeline.buildOrBug`。タグの種類は Order を持つ enum。敵の動きは時刻表の上で一斉に見せる（攻撃だけ順に）。カメラの追従は遊びの時計で進める（Cards で止まる）。`realT` は持たず `frame#realNow` を使う
- **松明の炎（人の注文: 赤めの炎）**: 炎は光を受けない色だけで描く（濃い赤 (1.0, 0.10, 0.01) 前後）。松明の点光源は赤寄り (1.0, 0.30, 0.08) で弱め。トーンマップで明るい赤が白へ寄るので、炎は明るさを上げすぎない（Blender の AgX では白く飛んだ）。揺らぎは実時間で大きさと明るさを少し揺らす。色と強さは look.json

## 13. 空腹と持ち物の枠（人の注文）— 数・油の壺・枠の左から は古い。§18・§19 が正
### 空腹
- 満腹度 最大 100。`hungerEvery`（Doc・3）手ごとに 1 減る（移動・待つ・殴る・ダッシュの 1 歩も 1 手）。0 の間は 1 手ごとに HP −1、自然回復は止まる

## 19. レビュー 2 回目（86 点）の残りへの答え
